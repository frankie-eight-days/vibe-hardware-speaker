\section{How it was designed}\label{sec:process}

This section tells the story of the design process. It draws on the process log \src{docs/process_log.md}, the build notes and the agents' own documents, and it keeps their account of what went wrong.

\subsection{The cast}

\begin{description}[style=nextline,leftmargin=1.2em]
  \item[The user] One person. They made every product decision (driver set, battery type, form factor, ``these schematics look awful'') and supplied a skill for redrawing schematics.
  \item[The lead] One orchestrating Claude session. It wrote the requirements file before any agent ran. It then split the work, wrote each agent's brief, relayed findings between agents and updated \texttt{docs/requirements.md} whenever a decision changed.
  \item[The agents] Separate Claude instances, each with its own context: three research agents, two circuit-specification agents, one mechanical-concept agent, one schematic-build agent and one review agent, and two simulation agents. Some of them started sub-agents of their own. \emph{No agent ever saw another agent's transcript}, only the files on disk and the messages the lead (or, by arrangement, another agent) sent it.
\end{description}

\Cref{fig:workflow} is the core idea: \textbf{files are the contract}. A message can arrive late or out of order, or be misread. A file has a path and a version, and every later agent can read it. Each stage's output is written for a reader that knows nothing about the conversation that produced it. The specs say so explicitly: ``written so the schematic can be drawn without datasheets: every pin, value, net and footprint is below'' \src{docs/spec_power.md}.

\paragraph{Gate 3, the release review.} One agent ran the user's \texttt{review-schematic-release} skill on a hashed snapshot of the design \src{docs/review/release_review.md}. It worked through all 44 checklist IDs, without editing the design. It:
\begin{itemize}
  \item traced eleven \emph{boundary states} on the exported netlist: dead or absent pack, pack insertion, blank firmware, ship mode, PVDD short, watchdog crash, weak USB source, cold start and others;
  \item checked every symbol pin against a footprint pad by script for all 257 references;
  \item compared custom footprints against the dimensioned drawings, and checked all 34 high-risk LCSC codes for lifecycle and stock;
  \item dismissed six of its own hypotheses after checking datasheets, including the CH224Q footprint orientation that the build notes had left open.
\end{itemize}
Its verdict: \textbf{no blockers; placement may proceed with conditions.} \Cref{tab:register} is its issue register, with the stage each item blocks and where it went.

One pattern stands out: S1, S2 and S3 were all consistent with the spec, so gates 1 and 2 could not catch them. The spec had accepted the removal of the disconnect FET \emph{assuming firmware}, quoted a 40-pF capacitance that the datasheet gives as \qtyrange{15.5}{30}{\pico\farad}, and copied a register default from the sibling part BQ25798. Only a review that asked ``what if the firmware is blank?'' found them.

\subsection{What worked}

\begin{itemize}
  \item \textbf{One requirements file and spec files as the contract between agents.} When the usage limit stopped every agent mid-run, nothing was lost, because nothing important lived only in a context window.
  \item \textbf{Splitting ``knows the datasheet'' from ``draws the schematic''.} The spec agents had web access and wrote for a drawing agent that had none. Their ``Decisions and changes vs.\ the brief (read first)'' sections are where most of the real engineering catches surfaced (\cref{sec:decisions}).
  \item \textbf{Independent review, then a challenge pass.} The review agent's two pinout concerns were checked by the spec agent against the datasheets and refuted. A reviewer's claim is a hypothesis, not a defect.
  \item \textbf{Netlist comparison as the safety net for cosmetic edits.} The redraw touched every sheet. Comparing (reference, pin) groups between the archived v1 and the redraw showed 0 differences, by net name and independent of names \src{hw/mainboard/BUILD_NOTES.md}.
  \item \textbf{Validation before use.} Every simulation was checked against an analytic or published case before its results were trusted: a sealed-box resonance to \qty{0.01}{\hertz}, electroacPy to \qty{0.013}{\decibel}, a piston on a sphere to \qty{0.34}{\decibel} at $ka = 7.3$, Leissa's clamped plate to \qty{1.5}{\percent}, TI's NTC reference table to within 0.5 percentage points of REGN, and a conformal-mapping line impedance to \qty{0.1}{\percent} (\cref{sec:analysis}).
\end{itemize}

\subsection{What went wrong}

\begin{itemize}
  \item \textbf{Out-of-order corrections.} During the \qty{4}{\ohm}/\qty{8}{\ohm} flip-flop the driver agent received the lead's corrections in a different order from the one they were sent in. It built, reverted and rebuilt its files. The decision had no single owner and no version number.
  \item \textbf{Instructions that arrived after the work started.} ``Pilot one sheet first'' reached the schematic agent after it had already redrawn all nine sheets with four sub-agents. The netlist comparison made the redraw safe anyway, but the user lost the chance to steer the style on one sheet first.
  \item \textbf{Resource exhaustion.} Heavy BEM, FEM and SPICE runs in parallel exhausted disk and RAM. The acoustics README now says ``one heavy job at a time'' (peak RAM $\approx \qty{3}{\giga\byte}$, about \qty{2.5}{\hour} for a full rerun) \src{sim/acoustics/README_head.md}.
  \item \textbf{Tooling surprises.} Konnect tools enabled with \texttt{load\_toolset} mid-session were not visible to the agent that loaded them, only to agents started afterwards. The build therefore had to run as one setup agent and then one agent per group of sheets \src{hw/mainboard/BUILD_NOTES.md}. Konnect 0.12.1 also cannot set KiCad's DNP attribute or title-block fields (\cref{sec:schematic-deviations}).
  \item \textbf{Duplicate notifications.} Agents sometimes repeated or duplicated their completion messages, and the lead had to deduplicate them.
  \item \textbf{Drift between documents.} Decisions taken late did not always reach every file. \Cref{sec:inconsistencies} lists the remaining conflicts between source documents.
\end{itemize}

\subsection{A playbook for designing hardware with LLM agents}\label{sec:playbook}

These rules come from what happened above. Each one names the incident behind it.

\begin{enumerate}[label=\textbf{R\arabic*.},leftmargin=2.4em]
  \item \textbf{Write the requirements file before the first agent runs, and keep it current.} Mark each line ``decided'' or ``open''. It is the only memory all agents share.
  \item \textbf{Make files the interface and messages the pointers.} Give every agent a fixed output path and a format (tables, units, net names). A message should say ``read \texttt{docs/spec\_power.md} §4.1'', not paraphrase it.
  \item \textbf{Give every decision one owner and a version.} Never send a correction until the agent has acknowledged the previous one. Use ``PVDD v2 = \qty{18}{\volt}'', not ``actually, change it back'' (\qty{4}{\ohm}/\qty{8}{\ohm} flip-flop).
  \item \textbf{Put pilots and stop points in the first brief.} ``Do one sheet, then stop and report'' only works if it arrives before the work starts (redraw).
  \item \textbf{Separate research from drawing.} Agents with web access write pin-exact specs; a tool-driving agent draws from them. Ask for a ``changes vs.\ the brief'' section at the top of every spec (ADR/FAULT, CH224Q, disconnect FET).
  \item \textbf{Review independently, then challenge the review.} Send each claimed defect back to the author with a request for datasheet evidence (two refuted pinout concerns).
  \item \textbf{Archive before any cosmetic change and verify by netlist.} Compare (reference, pin) sets, not pictures (redraw: 0 differences).
  \item \textbf{Validate every simulation against an analytic case first,} and record the error next to the result (\cref{sec:analysis}).
  \item \textbf{Review the boundary states, not just the drawing.} Ask the release reviewer to trace blank firmware, pack insertion, ship mode and shorts on the netlist (S1--S3 were consistent with the spec and invisible to gates 1--2).
  \item \textbf{Make simulations end in design changes.} Ask for findings as an ECO table with severity, evidence figure and status (ECO-001).
  \item \textbf{Schedule compute like a shared lab.} Run one heavy job at a time, cache results, and watch disk and RAM (\qty{150}{\mega\byte} free).
  \item \textbf{Assume interruption.} Everything an agent needs to resume must be on disk (5-hour usage limit).
  \item \textbf{Fix coordinates, units and conventions in one document.} The CAD, BEM and FEM all used the frame from \texttt{mech\_envelope.md}, so geometry flowed from FreeCAD into the BEM without hand edits.
  \item \textbf{Ask agents to label measured versus estimated facts.} The firmware research tagged every claim \texttt{[measured]} or \texttt{[estimate]}, which made its numbers easy to trust or discount.
  \item \textbf{Start fresh agents after changing their tools} (Konnect toolsets).
\end{enumerate}
